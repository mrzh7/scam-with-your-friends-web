# Admin 用户列表与运营统计

以现有管理员身份登录后，手动访问 `/admin`。后台包含“运营统计”“用户列表”和原有“网站服务管理”三个页签。权限要求、AI/TTS 配置、账号开关和部署配置均沿用原有设置；新增功能不需要数据库迁移，也不会修改玩家数据。

## 用户列表

仅展示注册账号（`guest=0`），按注册时间倒序、用户 ID 升序排列。同一注册时间的账号翻页时有稳定顺序。支持昵称、邮箱、用户 ID 的包含搜索，每页 25 人；特殊字符 `%`、`_`、`\` 按字面搜索。

字段包括昵称、用户 ID、邮箱、已配置的登录方式、注册时间、最近存档时间、房间存档数。没有存档或只有初始化存档的账号有单独提示。列表不包含密码散列、盐、会话令牌、OAuth subject、完整存档或服务密钥。

## 统计口径

- **注册用户总数**：当前数据库中的注册账号，包含管理员，不包含匿名游客。
- **近 24 小时／7 天／30 天新增**：从数据更新时间向前滚动相应时长，包含起止边界的注册账号数。
- **近 24 小时／7 天／30 天活跃**：相应窗口内有成功单人存档写入（`revision > 0`）或多人房间存档更新的去重账号数。首次读取时创建的单人初始化存档不计活跃。多人房间更新可能同时更新多个成员的存档；这衡量的是存档活动，不是在线人数、登录次数或精确游玩时长。
- **有云存档用户**：有单人或多人存档的去重注册账号，包含初始化存档。
- **已保存房间数**：与注册账号关联的房间存档，按房间码去重，包含历史房间，不代表实时在线房间。
- **近 30 天注册趋势**：今天及之前 29 个 UTC 自然日，缺失日期补零，今天显示截至刷新时的部分数据。这与“近 30 天新增”的滚动时间窗口不同。

用户时间和数据更新时间按浏览器时区显示，趋势日期明确使用 UTC。点击“刷新数据”可重新读取。统计根据现存数据计算；不提供访问量、支付收入或历史每日活跃曲线。

## 只读接口

- `GET /api/admin/users?q=关键词&page=1&pageSize=25`：返回 `users`、`total`、`page`、`pageSize`。关键词最多 100 字符；页码为 1–1,000,000；每页 1–100 人。超出结果范围返回空列表。
- `GET /api/admin/stats`：返回汇总指标、服务器 `generatedAt` 毫秒时间戳、30 天 `registrations` 数组。

两条接口都调用既有服务端管理员身份校验，未授权返回 403；仅支持 GET，其他方法返回 405；响应使用 `private, no-store` 和 `Vary: Cookie`。无需 AI/TTS 密钥或 `SITE_SETTINGS_KEY` 即可读取报表，服务配置本身仍遵循原有要求。

开源版保持 `ACCOUNTS_ENABLED=false` 为默认值；账号关闭或未设置 `ADMIN_EMAIL` 时，页面和两条新增接口均不可访问。需要后台时仍按既有部署指南启用账号和 Google 管理员身份。

## 验证

`tests/admin-reports.test.ts` 使用 SQLite 验证查询、权限、分页、搜索转义、时间边界和去重；开源版额外验证关闭账号或缺少管理员邮箱时拒绝访问。

运行 `npm test`、`npm run check:i18n`、`npm run build`。构建完成后运行 `node scripts/test-admin-browser.mjs`，验证真实页面的搜索、翻页、错误重试、配置保存、五语切换和手机布局。浏览器检查使用合成 API 数据，不访问真实账号或服务商；默认使用本机 Chrome，可通过 `PLAYWRIGHT_CHANNEL` 指定已安装的兼容浏览器。截图输出到被 Git 忽略的 `.local-config/admin-browser/`。
